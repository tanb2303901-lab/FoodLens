# DB-01 Thiết kế database và hợp đồng API

Ngày: 2026-10-14. Người thực hiện: Codex trực tiếp theo yêu cầu chủ dự án. Phụ thuộc: DATA-01 đã đạt. Trạng thái: DONE cho thiết kế; kết quả tại docs/reviews/DB-01-design.md. Chưa áp dụng schema hoặc kiểm thử API/DB runtime.

## Mục tiêu

Chốt thiết kế v1 đủ cụ thể để viết migration, kiểm thử phân quyền và FastAPI mà không tự quyết lại những quy tắc về ID, approval, snapshot, owner hoặc retry. Đây là bước thiết kế; migration/API runtime sẽ được triển khai và kiểm thử trong task kế tiếp.

## Tiêu chí nghiệm thu

- Phù hợp SRS, giữ 67 classes, 9115 references, 109 candidates, zero approved profiles/servings khi import.
- UUID tách khỏi index model, có thuật toán/namespace cố định và file map kiểm tra được.
- Schema ngăn liên kết cross-owner, profile/portion sai food/variant và nutrient snapshots do client tự gửi.
- Có quy tắc profile version bất biến, grams-only edit, optimistic concurrency và retry idempotent.
- RLS đi cùng grants; ordinary user không có đường trực tiếp ghi approval hoặc giả nutrient/detector output. RPC có quyền tối thiểu và checks bắt buộc, private bucket không đọc chéo owner.
- API có shapes cụ thể, errors/status rõ; nutrition_unavailable vẫn lưu được, core readiness không bị model chưa ready làm mất manual meal flow.
- JSON parse được, internal refs/route parameters/operation IDs và sample shapes nhất quán; không gọi việc này là test API/DB runtime.
- Ghi rõ Docker/WSL2/CLI setup cần cho task sau, không đòi secrets để thiết kế.

Đối chiếu SRS, tài liệu chính thức Supabase/PostgreSQL/OpenAPI, tạo và kiểm tra file class map với CSV nguồn, kiểm tra cấu trúc contract và self-review các luồng owner/snapshot/retry. Không thêm tests chỉ để khẳng định các câu trong tài liệu. DB-02 phải chạy tests migration/RLS thật trước khi coi thiết kế đã được thực thi.
