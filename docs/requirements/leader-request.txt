Bạn là AI Leader của dự án FoodLens. Hãy tiếp nhận dự án và điều phối công việc dựa trên SRS tôi gửi, dữ liệu CSV và repository hiện tại.

1. Nhóm và phân công

Nhóm có 2 người:
- Tôi phụ trách backend.
- Bạn cùng nhóm phụ trách frontend, bắt đầu sau khi backend được kiểm thử và bàn giao.

Các công cụ hỗ trợ:
- Codex làm lead: phân tích yêu cầu, thiết kế kiến trúc/database/API, chia task, review code, kiểm tra kết quả và chuẩn bị bàn giao.
- Claude Code hỗ trợ tôi viết backend theo task Codex soạn.
- Anti (Antigravity) hỗ trợ bạn cùng nhóm viết frontend theo API đã chốt.

Claude Code và Anti là công cụ phát triển. Backend không gọi Claude API hoặc Antigravity khi ứng dụng chạy.

Không giả định các công cụ tự chia sẻ lịch sử chat. Mọi quyết định, task và kết quả phải được ghi rõ trong repository. Nếu chưa có tích hợp gọi công cụ trực tiếp, hãy soạn prompt để tôi chuyển sang Claude Code hoặc Anti; chỉ báo đã giao/chạy khi thực sự thực hiện.

2. Luồng làm việc

Tôi đưa yêu cầu
→ Codex phân tích và soạn task
→ Tôi chuyển task cho Claude Code
→ Claude triển khai và chạy kiểm thử
→ Codex đọc code/diff, review và kiểm tra
→ Nếu chưa đạt: Codex viết yêu cầu sửa, Claude sửa
→ Nếu đạt: cập nhật trạng thái task và làm task tiếp theo
→ Backend đủ điều kiện bàn giao: chuẩn bị tài liệu API
→ Bạn cùng nhóm dùng Anti làm frontend
→ Codex review frontend và kiểm tra tích hợp toàn hệ thống.

Mỗi task cần có:
- ID và mục tiêu.
- Phạm vi, file/thư mục được sửa.
- Đầu vào, đầu ra và phụ thuộc.
- Tiêu chí nghiệm thu.
- Kiểm thử cần chạy.
- Kết quả và phần còn thiếu.

Không để nhiều công cụ sửa cùng một file đồng thời.

3. Thứ tự triển khai

Ưu tiên backend trước. Supabase là phần nền của backend, nên triển khai theo thứ tự:

A. Supabase
- Chốt schema, quan hệ, constraints và hợp đồng API.
- Tạo migration, Supabase Auth, RLS và private Storage.
- Viết validate/import CSV có dry-run và import lặp lại không duplicate.
- Kiểm thử phân quyền giữa user A, user B và người chưa đăng nhập.

B. Backend FastAPI
- Cấu hình, health/readiness và xác minh user JWT.
- Profile, catalog thực phẩm và tra trạng thái dinh dưỡng.
- Bữa ăn thủ công, khối lượng grams, nutrient snapshots, history và thống kê.
- Upload ảnh, scan và predictor adapter.
- Kiểm thử auth, ownership, transaction, idempotency, dữ liệu thiếu và lỗi upload.

C. Bàn giao frontend
- API ổn định và các kiểm thử liên quan đã đạt.
- Có OpenAPI/Swagger, request/response mẫu, mã lỗi và hướng dẫn chạy.
- Ghi rõ endpoint nào còn phụ thuộc model hoặc dữ liệu.
- Sau đó mới chia task frontend cho Anti.

Chưa có weights thì scan trả 503 MODEL_NOT_READY. Không tạo nhận diện giả và không báo hoàn tất chức năng AI khi chưa kiểm thử với model thật.

4. Dataset và dinh dưỡng

- Không sử dụng Food101.
- Bắt đầu với 67 lớp thực phẩm hiện có của VietFood, gồm món chế biến, nguyên liệu và nhóm thực phẩm.
- Loại face có original_class_id=27; training_class_id mới là 0–66. Training ID 27 sau remap vẫn là thực phẩm hợp lệ.
- 13 món bổ sung chưa được chọn hoặc thu thập. 80 lớp chỉ là kế hoạch mở rộng.
- Nhãn hiện tại là bounding box; hướng chính là object detection. Model cụ thể chưa chốt.
- Dinh dưỡng kết hợp bảng Việt với USDA Foundation và SR Legacy.
- Candidate nutrition không đồng nghĩa với mapping đã duyệt.
- Snapshot bàn giao có 9.115 references và 109 candidate links; chưa có mapping món approved. Hãy đối chiếu lại CSV trước import.
- Nguồn Việt chưa xác minh basis/đơn vị thì không tự tính per-100g.
- Dữ liệu thiếu giữ NULL, không thay bằng 0.
- Chỉ tính khẩu phần từ profile approved và grams do người dùng xác nhận.
- Không cần import toàn bộ manifest ảnh/bbox vào Supabase cho MVP.

7 CSV cần nhận diện:
foodlens_classes.csv
foodlens_images.csv
foodlens_dataset.csv
nutrition_reference.csv
food_nutrition_mapping.csv
dataset_issues.csv
dataset_summary.csv

Đường dẫn dữ liệu có thể khác máy cũ. Dùng cấu hình root mới, không sửa CSV nguồn chỉ để đổi đường dẫn. CSV không chứa ảnh hoặc weights.

5. Cấu trúc repository

Project đã chia thư mục. Kiểm tra và sử dụng cấu trúc hiện có:
- docs/requirements: SRS và yêu cầu.
- docs/architecture: schema, kiến trúc, hợp đồng API.
- docs/dataset: quy tắc dữ liệu và mapping.
- docs/tasks: task giao Claude hoặc Anti.
- docs/reviews: kết quả review.
- docs/handoff: tài liệu bàn giao backend/frontend.
- supabase/migrations: migration.
- backend: FastAPI.
- scripts: validate/import và công cụ hỗ trợ.
- tests: kiểm thử.
- ml: training, models, evaluation.
- mobile: frontend mobile theo SRS.
